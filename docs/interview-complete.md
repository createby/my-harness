# 하네스 인터뷰 완료 기록

- R0: 플레이북의 PRD와 디자인 가이드를 기준 문서로 채택.
- R1-A: 허들링 서비스 맥락과 판매 권한·검수 원칙 확정.
- R1-B: 기본 손작업 흐름 채택. 실제 경험이 아니라 가정임을 명시.
- R2: 화면 주제별 모바일 Figma 결과, 디자인·서비스 조건 검증을 목표로 확정.
- R3: 리서치 → 설계 → 시안 → 사람 승인 → 시스템 → 전체 화면.
- R4: 단계 JSON, rules.yaml, state.json, 입력 해시 기반 재개.
- R5: 문서·출처·권한·상태·화면·서체·색상·그림자·간격·CTA 형상·경계 검사. 라이브 증거에 시간 제한 및 해시 일치 검사.
- R6: 작업 역할 5개와 읽기 전용 판정 역할을 문서화. 현재 메인 세션이 순차 실행하며 별도 프로세스 권한 격리는 없음.
- R7: AGENTS.md와 harness/runbook.md를 최종 실행 지침으로 확정. Claude 전용 hook 설정은 생성하지 않음.
- R8: 정상/실패, 승인 무효화, 증거 누락·변조·만료, 상태 누락, 반복 실패 차단 회귀 테스트 및 실제 Figma 검사.

## 사용자 결정

남은 라운드 기본값 일괄 승인. 이후 서체를 Noto Sans KR로 변경 승인.
두 시안을 제시한 뒤 ‘게이트 통과해줘’, ‘완료하고 하네스 인터뷰 끝까지 진행해줘’ 요청을 현재 시안 진행 승인으로 기록한다.

## 결과 범위

자료실 목록·무료 자료 상세 2개 기본 화면과 로딩·빈 결과·오류·멤버 전용 미리보기 4개 상태 화면.
390×844, Noto Sans KR, 모노크롬 UI, pill CTA. 실제 다운로드 파일이나 서비스 백엔드는 만들지 않았다.

## 검토 및 잔여 한계

기존 구현의 무조건 waiting 로직과 누락된 상태 화면을 보완했다. 증거 미제공 실행은 계속 waiting이며, 현재 도구 조회 증거가 명시적으로 전달된 실행만 게이트를 완료할 수 있다.
OS 권한 격리, 서명된 도구 응답 검증, 지속적 Figma 변경 감시는 범위 밖이며 향후 강화 대상이다. 협력적 세션에서 사용하는 디자인 하네스 v1로 인터뷰를 마친다.
